- **背景**：T-012 已验证一条完整链路可用：玩家做表情 → 认出召唤者的随从 → `ActionComponent.Execute(..., layer: ActionLayer, forceExecute: true)` 让随从立即放指定招式。但它写死了「沃里克 + 凶残之力 + 延迟范围攻击」。维护者希望做成通用机制：任何召出的 Boss／敌人都能用，不同召唤物对不同表情有不同反应。
- **目标**：用一张「反应表」描述「哪类召唤物 × 哪个表情 → 放哪一招」，插件按表执行；T-012 的沃里克规则成为表里的一条默认规则，行为不变。

## 设计规划（待审批）

### 1. 反应表

- 放在单独的 `UserData/NRFWNecromancyReactions.json`（规则多、要分组，cfg 一行字符串不好写）；文件不存在时插件写出带注释示例的默认表，只含 T-012 的沃里克规则。
- 每条规则：
  - `who`：匹配召唤物，按优先级依次为 NPC 资产 GUID → T-013 的配置名（如 `boss`、`warrick`）→ 敌人档位（Boss / 巨型 / 精英 / 普通）→ `*`。
  - `gesture`：表情 GUID（默认表附 47 个表情的 GUID 与名字对照）。
  - `action`：动作（ActionData）GUID；可给多个，配 `pick: first | random | cycle`。
  - `cooldown`：秒，默认 3。
  - `mode`：`force`（默认，T-012 的立即打断执行）或 `prefer`（见第 4 节）。
- 匹配：对召唤者名下每只随从取最具体的一条规则，各自执行；没有规则的随从不受影响。

### 2. 执行

- 复用 T-012 已在实机验证的代码路径：命令钩子 `CommandProcessingSystem.ExecutePerformGesturePlayerCommand`、确认帧执行、Owner 经组件指针读、NPC 经 `NpcAttachmentComponent.NpcData` 读、`Has/Get<ActionComponent>`（不用 `TryGetPointer`）、动作层 `ActionComponent.ActionLayer`、+0.5 s／+1.5 s 执行追踪。
- 抽成「反应执行器」：输入（随从、动作、模式），输出结果并写日志；T-012 的沃里克专用代码改走这个执行器。

### 3. 动作目录与校验（让表好写、写错能发现）

- 运行时资产路径为空，只能用 GUID。离线工具从 `qdb_assets_all` 包读出每个资产的名字与 GUID（T-012 已验证读法），生成本地对照表：每种敌人的动作名 → GUID、全部表情名 → GUID。对照表只留本地，不进公开仓库；仓库只放生成脚本。
- 运行时校验：配置的 GUID 不是 ActionData 时记一次实际类型（T-012 已有）；随从首次出现时可选记录其 AI 动作列表（`AiControllerData.ActionList → ActionGroups → Actions`）里的动作 GUID，用来判断这招是不是这只随从本来就会。
- 放别人的招（例如普通兵放 Boss 招）不禁止，但日志标明「不在其动作列表」，作为高风险。

### 4. 可选：`prefer` 模式（走 AI 自己的选招）

- pi 元数据摸底（2026-11-28）确认游戏没有现成的「指定下一招」排队接口。最接近的是 `ActionSelectionParams.CalculateScore`：做表情后给该随从、该招的评分临时加权，下一次 AI 选招时优先选它，并保留原有的目标、距离、冷却和打断判断；招式开始后清除请求。
- 只对随从动作列表里本来就有的招有效。放在第二阶段，先保证 `force` 通用化。

### 5. 与 T-013 的关系

- T-013（`t/T-013-minion-profiles`，未合入）给每只随从一个配置名（`MinionProfileName`）。本单的 `who` 用它作为第二优先级的键。
- T-013 未合入前，本单只用 NPC GUID 和敌人档位匹配，接口留好，T-013 合入后接上。

### 6. 分阶段

1. 反应表读取、匹配与执行器；沃里克规则迁入默认表；纯逻辑测试（匹配优先级、冷却、坏配置被拒）。
2. 离线动作／表情对照表脚本；运行时动作列表记录与「不在列表」警告。
3. 多招 `pick`、按召唤物分组的默认表（例如几个常见 Boss 各配一套）。
4. （可选）`prefer` 模式。

### 7. 测试

- 第 1 层：构建 + 审计（钩子与调用签名、禁用 `TryGetPointer` 检查保留）+ 规则匹配纯逻辑测试（含必须被拒的输入）。
- 第 3 层（维护者试玩）：沃里克 + 凶残之力行为与 0.16.x 一致；再选一种别的 Boss 召出，配一条规则验证通用性；两个不同表情触发两种不同招式。

### 8. 风险

- 部分招式依赖 Boss 战协调器、阶段或多人条件，单独强制执行可能无效或卡住；靠执行追踪日志发现。
- 强制打断会让随从放招时不看目标、距离；`prefer` 模式可缓解。
- 别的召唤物（非 raiseMinion 换出来的）目前只有 revive 起尸体原本的敌人，T-010 的召唤目标仍只能配一种；「召唤哪个 Boss」不在本单范围。
- 仅单机。
