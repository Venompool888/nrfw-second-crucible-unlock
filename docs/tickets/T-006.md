- **实际**：召出的随从和玩家之间会互相造成伤害。
- **期望**：随从↔玩家、随从↔随从不互伤；玩家↔玩家保持原版判定（联机友伤不变）；随从打敌人照常。
- **修法**：后缀挂 `TeamUtils.AreAllies`，按规则把含随从的配对判为盟友；规则有纯逻辑测试覆盖全部组合。
- **待确认**：随从若用投射物攻击，伤害来源可能记在投射物上而不被拦截，看试玩日志。

## 进度记录

- 2026-11-26 维护者要求去掉随从误伤、保留联机玩家友伤；0.9.0 实现，待试玩。
- 2026-11-26 0.10.0 试玩：维护者疑似仍被随从打到；日志没有任何拦截记录。原因：随从在玩家阵营，`AreAllies` 原本为真，伤害走友伤系数。0.11.0 改为在 `DamageAPI.IgnoreDamageRequest` 按 `Damage.Proxy` 来源忽略随从相关伤害，`GetFriendlyFireCoefficient` 置 0 兜底，待试玩。
- 2026-11-26 **0.11.0 回归**：装上后玩家打不到敌人。日志没有闸门记录也没有异常，判断是按引用传 `Damage` / 按值返回 `FP` 的两个 detour 本身破坏了全部伤害。0.11.1 紧急移除，伤害回到 0.10.0；随从友伤待用不碰伤害结构体的办法重做。教训：改动伤害主路径的 hook 必须先做最小实机验证再叠加逻辑。
- 2026-11-26 0.12.0：不碰伤害结算。随从首次出现时若在 `teamDataPlayers`（有友伤）就改到原版 `teamDataPlayersNoFF`（无友伤）；新增只读诊断（`CharacterViewEffects.OnDamageResolved` 记录随从相关的每一下伤害，`AreAllies` 原版为真的随从配对）。待试玩：先确认玩家打敌人正常，再看日志里有没有 `HIT hero=... by minion` 且 taken>0。
- 2026-11-26 0.12.0 试玩：8 个随从全部 `Players -> PlayersNoFF`；整局没有随从与玩家互伤的记录（`HIT` 0 条），玩家打敌人正常。待维护者确认体感无友伤后转已验证。
- 2026-11-26 维护者反馈 0.12.0/0.12.1 仍会掉血，但日志没有随从相关的受击记录。推测：Boss 随从的范围技能 `TargetGroup` 为 `Both`（不分阵营），或伤害来源是随从放出的投射物或衍生体。0.12.2 只加只读诊断（`HeroView.OnDamageResolved` 记录玩家每次受击的全部来源代理、`TargetGroup`、标记和掉血量），待试玩取证。
- 2026-11-26 维护者指出「有没有受到随从伤害」仍未确定。核对 0.13.0 日志：`HERO HIT` 的来源值都是 0~4，不是实体编号——互操作结构把 `PayloadProxyGroup` 的定长代理缓冲建模成 1 个元素，托管副本被截断，`Main` / `TryGetProxyOfType` 读到的是垃圾，所以 `FROM-MINION` 永远不会出现，此前「没有随从伤害」的结论作废。0.13.1 改为从原生事件内存按 IL2CPP 偏移读全部代理槽（布局校验不过就不读），待试玩复核。
