- **复现**：0.13.1 正常战斗中游戏崩溃。Player.log 显示 `PathFollowingSystem` → `PathFollowingComponent.SearchPath` → `AttachmentAPI.ResolveNavDataAttachment` 对 4 个实体每帧抛 `InvalidOperationException: E.x does not have this component type : Quantum.UseNavDataComponent`，18 秒约 1200 次后游戏以 "too many exceptions" 自行终止（WER 0xc0000409）。同版本另一局未复现。
- **原因（静态分析，部分推断）**：`ResolveNavDataAttachment` 无条件 `Frame.Get<UseNavDataComponent>`，缺组件即抛；`SearchPath` 对空返回直接解引用，所以不能让它返回空。`SpawningAPI.SpawnEntity` 在出生点找不到活动导航网格时不加该组件（推断：随从在离网格处被召出，或其他 NPC 同样情况）。4 个实体是不是随从未确认——当时插件日志已到条数上限。
- **修法**：`PathFollowingComponent.SearchPath` 前缀，寻路主体缺 `UseNavDataComponent` 时跳过这次寻路（原本会抛异常），每个实体记一次 `GUARD`；`ResolveNavDataAttachment` 只读探针记其他仍会走到抛异常的调用；每 5 秒随从名单（`E.index.version`）；放开召唤／着色／传送／受击日志上限。
- **静态分析附带发现（T-009）**：随从传回有三种触发——离主人超过 `MaxDistanceBeforeTeleport`（召唤时复制进随从组件）、高度差超过 3 米、卡住（跟随中或有攻击目标时 3 秒内移动不到 0.5 米）。0.13.1 日志里 2.8~24.5 米的频繁传送是卡住触发，和距离倍数无关。是否改卡住传送待维护者决定。
- **决定（维护者 2026-11-26）**：打怪时不拉回。0.13.4 在 `RaisedMinionSystem.Update` 前，对 AI 有存活攻击目标（`AiControllerComponent.AttackTargetRef`，`ExistsAndNotPendingDestruction`）的随从把 `StuckDuration` 清零；跟随中真卡住、超过 60 米、高度差超过 3 米的传回不变。配置 `minion_stuck_teleport_in_combat`（默认 false，true = 原版）。
- **待确认**：试玩时出现 `GUARD` / `NO-NAV` 行时，看实体是不是随从；跳过寻路后该实体是否会卡在原地。
