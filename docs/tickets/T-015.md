- **背景**：T-010 把原版 raiseMinion 的召唤目标整体换成了沃里克，只能配一种。维护者希望做一套**自己的**死灵召唤符文：每枚符文召出一种指定的 Boss，有自己的名字、说明和图标，可以同时拥有、换着用。
- **首批**：
  - 沃里克：npcWarrickBoss（`2680182020363611965`，Boss），沿用 T-010 已验证的目标。
  - 回声骑士：npcEchoKnightBoss（`790324362694538264`，Boss，AI echoKnightAiControllerData `805792732544777101`）。数据里另有骑马版 npcEchoKnightMountedBoss（`1477811819341278935`）和两个瘟疫版（PlagueSystem），默认用步战版。
- **图标**：维护者自己设计，做好后交给会话。插件从 `UserData/` 下的 PNG 读图标，替换这几枚符文在背包、镶嵌、技能栏上的显示；没有图片时退回原版起尸符文图标，不影响使用。
- **目标**：以后加一种 Boss 符文只需在配置里加一条（Boss 的 NPC GUID + 图标文件 + 名字），不改代码。

## 设计规划（待审批）

### 1. 符文从哪来（关键技术选择）

- **方案 A（建议）：运行时克隆新资产。** 以原版 raiseMinion 符文（`2160606268309502004`）和它的起尸动作（`22455697660660456`）为模板，在资产库加载后各克隆一份，分配插件自己的固定 GUID；动作里的 `MinionNpcData` 指向目标 Boss，`UseCorpseNpcType=false`。新符文追加进运行时符文表，和原版死灵符文一样可镶在长杖／魔杖／治疗宝典上。数量不受限。
  - 要先核实：Quantum 资产库能否在运行时追加资产且不破坏确定性；符文表（运行时 index）能否追加；存档里存的是物品 GUID，插件不在时这些符文会变成未知物品——要确认游戏是丢弃、保留还是报错，并在卸载说明里写清。
- **方案 B（备选）：借用现成的未放出符文。** 拿几枚不会和现有功能冲突的未放出符文当载体，改它的动作为起尸、改图标和名字。存档兼容最好（GUID 本来就在游戏里），但载体数量有限，原符文的适配武器、动画可能不合适。
- 方案 A 第一步先做可行性验证（离线元数据 + 最小试玩：克隆一枚、发到背包、存档读档），不行再退到方案 B。

### 2. 召唤规则

- 每枚 Boss 符文召出自己配置的 Boss；按符文分别计数上限（默认每种 1 只）。生命和伤害沿用原版 Boss 档 ×0.1 缩放，可在配置里按符文覆盖。
- 是否仍需 8 米内有尸体、专注消耗多少，见「待决定」。
- 召出后照旧走 `RaisedMinionSystem`（跟随、传送、索敌）、T-006 防误伤、T-008 时限、T-011 防崩、T-013 分档（合入后）；T-014 反应表按 NPC GUID 匹配，回声骑士可以直接加自己的表情规则。

### 3. 名字、说明与图标

- 名字和说明由插件按符文 GUID 提供（中英文），替换原版「未命名」显示。
- 图标：先离线确认原版符文图标的尺寸、格式和取图入口（物品视图数据 → Sprite），再挂钩取图处，按符文 GUID 返回从 PNG 生成的 Sprite。图标规格（像素尺寸、透明底、留边）确认后写进本单，交给维护者照着做。

### 4. 配置

- 单独的 `UserData/NRFWNecromancyBossRunes.json`：每条 `{ key, npc, icon, name, description, max_active, health_scale, damage_scale }`；文件不存在时写出沃里克、回声骑士两条默认项。
- 发放：沿用现有按角色一次性发放（`grant_character` / `granted_characters`），每枚新符文各记各的，已有的不重发。

### 5. 分阶段

1. 可行性：方案 A 克隆一枚符文（沃里克），能发到背包、能镶、能召出、存档读档后还在。
2. 配置表 + 回声骑士 + 名字说明。
3. 自定义图标（拿到维护者的图后接入）。

### 6. 测试

- 第 1 层：构建 + 元数据审计（新钩子签名、克隆用到的字段偏移）+ 配置解析纯逻辑测试（坏 GUID、缺图、重复 key 必须被拒或回退）。
- 第 3 层（维护者试玩）：两枚符文都在背包且图标正确；分别召出沃里克、回声骑士，各最多 1 只，可同时在场；存档退出再进，符文还在；关掉插件看存档表现（只在备份角色档上试）。

### 7. 风险

- 运行时加资产是全新路线，可能碰到确定性校验、资产库只读、符文表固定长度等限制，届时退方案 B。
- 回声骑士离开 Boss 房生成，可能缺阶段脚本或竞技场依赖（沃里克已证明可行，但回声骑士未试）。
- 存档里留下插件自造的物品 GUID，卸载插件后的表现未知，必须先在备份档上验证。
- 两个 Boss 同时在场的性能与卡位。
- 仅单机。

## 待决定

2. Boss 符文还需不需要尸体？建议保留「8 米内有尸体」，和原版起尸一致；也可以改成无尸体直接召唤，代价提高（如 200 专注）。

4. 回声骑士用步战版还是骑马版？建议先步战版，骑马版以后作为单独一枚符文。
