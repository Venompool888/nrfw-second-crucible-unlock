- **背景**：raiseMinion 目前按原版数据固定召出「复生野人剑士」（`npcRisenWildlingSwordA`，NpcData `2598229157892424643`）。维护者希望起尸召出的是 Boss 沃里克（Warrick）。这也是后续「按表情指挥随从放指定招式」的前置：先要能召出 Boss。
- **范围**：只改 raiseMinion。revive（`UseCorpseNpcType=true`，起来的是尸体原本的敌人）和 healMinions 不变。
- **思路（待审批后核实）**：
  1. 从 QDB 找出沃里克的 NpcData 及其依赖（EntityData、Controller、View、Team），确认公测 22928553 里有几个变体（世界 Boss、试炼版、臃肿沃里克等）。
  2. 在 `RaiseMinionActionData.Execute` / `CanRaiseNearby` 前缀把召唤目标（`MinionNpcData` / `NpcToSpawn`，具体字段待反编译确认）换成沃里克，按资产指针记录，避免重复改写；加配置开关，关掉即恢复原版野人剑士。
  3. 召出后仍走 `RaisedMinionSystem` 的编队、跟随、传送、索敌，队伍与着色沿用现有逻辑。
- **风险**：
  - Boss 带阶段脚本、Boss 血条、竞技场音乐与镜头等依赖，离开 Boss 房生成可能缺依赖或行为异常（试炼里已有沃里克第二阶段目标、损坏音乐的修复先例）。
  - 沃里克的范围攻击可能误伤召唤者，T-006 的友伤问题未彻底解决。
  - 体型大，跟随、避让、传送可能卡位；同时 5 个（`MaxActiveMinions`）可能过强或过重。
  - 依赖资产未加载的区域生成可能失败，需要预加载或回退到原版随从。
- **决定（维护者 2026-11-26，按建议）**：
  1. 用普通世界 Boss 版 npcWarrickBoss（`2680182020363611965`，EnemyType Boss）。
  2. 沃里克最多同时 1 个。
  3. 沿用原版，仍要 8 米内有尸体。
  4. 先不保留 Boss 血条和阶段转换，只要本体和招式。
- **验收（维护者试玩）**：打死敌人后在尸体旁放 raiseMinion，召出沃里克；它跟随、攻击敌人、不攻击召唤者；日志记录召出的 NpcData GUID 与生成结果；关掉开关后召出野人剑士。

## 进度记录

- 2026-11-26 维护者要求起尸先改成召出沃里克，建单待审批。已确认 raiseMinion 原版固定召出 npcRisenWildlingSwordA；`RaiseMinionActionData` 相关字段名有 `MinionNpcData`、`NpcToSpawn`、`MaxActiveMinions`，哪个决定召唤目标尚未反编译确认。
- 2026-11-26 维护者按建议定下 4 项并批准开工。公测数据里沃里克有 4 个 NpcData：npcWarrickBoss（Boss）、npcWarrickEnemy（巨型，同一 AI）、npcWarrickBounty（巨型）、npcWarrickBossPlagueSystem（Boss，瘟疫版 AI）。决定召唤目标的字段是 `RaiseMinionActionData.MinionNpcData`（AssetRefNpcData），上限是 `MaxActiveMinions`（Int32），`UseCorpseNpcType` 区分 raiseMinion 与 revive。
- 2026-11-26 0.14.0 实现：沿用 `Execute` / `CanRaiseNearby` 前缀，只对 `UseCorpseNpcType=false` 的资产把 `MinionNpcData` 换成目标、`MaxActiveMinions` 压到 1；目标须先解析成 NpcData，否则保持原版；按资产指针记录写入值。新配置 `minion_npc`（默认 warrick_boss，可填 warrick_enemy / wildling / native / GUID）和 `minion_max_active`（默认 1，0 = 原版）。第 1 层：构建 0 警告，元数据审计 68/68，含 6 条新检查；把上限函数改坏后对应检查失败。沃里克按原版 Boss 档缩放，生命、伤害都是 ×0.1。
- 2026-11-26 暂未安装：游戏里现装的是 T-006 会话 22:10 刚装的 0.13.2（友伤修复，待试玩），本分支不含 T-006 改动，直接替换会让 T-006 失去试玩机会。安装方式待维护者决定。
