## 需求与目标

为死灵召唤玩法新增一件独立的自定义副手装备 **「死灵法典」**（英文如 `Necromancy Codex`）：

- **装备位置与形态**：副手装备（挂在左手），左手 3D 模型、持握待机、格挡与招架等基础动作模组基本套用原版「治疗宝典」（`tomeOfHealing`）。
- **自带符文与槽位**：自带 **沃里克**（`npcWarrickBoss`）与 **回声骑士**（`npcEchoKnightBoss`）两枚 Boss 召唤符文（不再带原版槽 0 的「治疗」符文）。
- **自定义外观与文案**：接入维护者设计的装备栏图标，并在背包、装备栏、详情页及左下角副手 HUD 显示自定义图标与「死灵法典」中英文名称及说明。
- **召唤抬手动作**：施放沃里克与回声骑士召唤符文时带有清晰的抬手施法动作，并梳理好与 T-018 回声骑士出场演出的衔接。

## 设计规划

### 1. 武器来源：方案 A（克隆独立装备）vs 方案 B（原位改治疗宝典）

- **方案 A（推荐）：运行时克隆独立副手武器「死灵法典」**。
  - 分配固定 `DynamicExplicit` GUID（如物品 `I_codex = 0xC000543032330001`、`ItemData L = 0x8000543032330003`、`RuntimeArmament Id = 0xC000543032330004`）。
  - 在 `InitializeContentSystem.OnInit` 后缀深拷贝 `WeaponStaticData(3937520191132810478)`（清空 `CraftingIngredients`、独立 `Path`），登记 5 张存储表（`WeaponData`、`EquipmentData`、`ItemData`、`CommodityData`、`ItemAttachments`）及专属空动作表 `RuntimeArmament`（`RuntimeActionSelection = new RuntimeArmamentActionSelection()`，不含 `heal.action`，从而彻底去掉槽 0 静态「治疗」）。
  - Unity 侧克隆 `WeaponStaticDataAsset` 注册进 `RuntimeAssetResolutionContext`（直接继承 `PrefabRef` 复用 `tomeOfHealingView.prefab`），并在 `ArmamentViewState.ViewsLookup` 将 `CodexArmamentGuid` 映射到原版 `tomeOfHealing` 的 `RuntimeArmamentView` 保留 `WwiseConfig` 音效。
  - 优势：完全不污染原版 `tomeOfHealing`，保留 T-001/T-008 原版治疗宝典与背包内并存能力。
- **方案 B（备选）：原位修改原版 `tomeOfHealing`**。
  - 改 `tomeOfHealing` 名字/图标/动作表会导致所有旧治疗宝典一并被替换并失去原版「治疗」符文，不推荐。

### 2. 符文槽位与兼容性

- **符文槽配置**：
  - **子方案 A1（推荐）**：以 `ItemRarity.Gold` 创建「死灵法典」（解锁 4 槽、`IsStaticSlot=0`），将沃里克写槽 0、回声骑士写槽 1，槽 2–3 留空供玩家镶入其他死灵符文或自由调整顺序，无需额外克隆 `ArmamentActionSelectionData` 或改动 `m_allRunes`。
  - **子方案 A2（备选）**：将槽 0/1 设为静态锁定（`IsStaticSlot=1`），不可覆盖或拆换。
- **符文兼容性**：
  - `IsRuneCompatible` 实体重载 `AfterCompatibleByEntity` 将白名单从单判 `TomeOfHealing` 扩为 `IsNecromancyTome(item)`（即 `TomeOfHealing || CodexItemGuid`），使死灵法典同时支持 Boss 符文及后续镶入死灵符文。
  - 指针重载 `AfterCompatibleByComponent` 校验 `weaponClass == 0`（`WeaponClass.None`）；克隆法典保持 `Class = WeaponClass.None (0)`，无需改动逻辑即可自动兼容。

### 3. 图标与文案

- 规范化后的 `512×512` 透明底 PNG 放于本机 `UserData/NRFWNecromancyBossRunes/`（不进公开仓库）；加载后同时写入克隆包装的 `ItemIcon` 与 `ItemTexture`（若缺图则退回原版治疗宝典图标）。
- 沿用 `HeroItemDataAsset.GetName()` / `GetDescription()` 延迟后缀，按 `CodexItemGuid` 返回中英文名称（如「死灵法典」/「Necromancy Codex」）与说明。

### 4. 发放演进与旧角色兼容

- 沿用 `boss_tome_character` 机制，改为等待「所有 Boss 符文 `ViewReady` **且** 死灵法典 `ViewReady`」后，创建金色 `CodexItemGuid` 法典并写入沃里克（槽 0）+ 回声骑士（槽 1）。
- 新增独立发放记录键 `@codex`（与旧 `@tome` 区分）：已领过旧治疗宝典（`character:@tome`）的测试角色可自动补发一本全新「死灵法典」，且不删改背包里已有的旧治疗宝典。

### 5. 分阶段实施计划

1. **模拟 + 视图克隆与读档可行性**：完成 `WeaponStaticData` 克隆、5 张存储表与空动作 `RuntimeArmament` 注册、`WeaponStaticDataAsset` 包装及 `ViewsLookup` 音效映射，确认可创建、可装备至左手且跨重启读档完整恢复。
2. **图标文案、槽位与发放接入**：接入 `512×512` PNG `ItemIcon` 与「死灵法典」名称说明，确认去槽 0 治疗、预镶沃里克/回声骑士符文、兼容白名单与 `@codex` 补发就绪。
3. **召唤抬手动作与 T-018 衔接微调**：按维护者决定落实抬手动画（默认 `castWall` 或改用候选动作）与回声骑士 `bestialPowerData` 衔接策略。

## 风险与未证实点

- **卸载插件后的存档边界**：存档写入自定义物品 GUID，卸载插件后读档会触发 `Failed to create or equip item entity` 并跳过法典，另存后会永久丢失；必须在备份档上验证，并在卸载说明中提醒备份或暂勿保存。
- **`ArmamentViewAPI.GetRuntimeArmamentView` 映射**：需实机确认将 `CodexArmamentGuid` 映射到原版 `tomeOfHealing` 的 `RuntimeArmamentView` 后，装备模型、音效与切换均正常且无 null 风险。
- **空动作表副手交互**：专属 `RuntimeArmament` 的 `RuntimeActionSelection` 为空，需实机确认格挡、招架、槽 0/1 技能触发及强化/附魔/出售/销毁界面无空引用或意外回退。
- **`castWall` 与 `HeroSecondaryItemView` 动画叠加**：需实机确认左手高举 `castWall` 期间 `HeroShieldView.HandleBehaviourDuringAction()` 与 `ShieldPoseAdditiveAnim` 是否造成法典穿模、错位或翻页异常（若改用 `specialBuff`/`specialRiseMagicShort`，还需核对 `raiseMinionView` 既有粒子/音效时序）。
- **回声骑士 0.50s 硬切观感**：需实机确认左手高举至 0.50s 时硬切 T-018 `emoteKingKong` 捶胸咆哮的视觉衔接是否自然。
- **仓储读档与联机范围**：储物箱读档走另一条持久化链，尚未单独核验；本功能仅支持单机。
