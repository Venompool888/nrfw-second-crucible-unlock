先确认这份教程适合你

本教程针对第一次安装 Mod 的 Windows Steam 玩家。你只需要 Steam、官方游戏、浏览器和 Windows 自带的文件资源管理器与 PowerShell。

这个 Mod 做什么

在 Mod 正常加载时临时开放第二回声，并修补第二盆献祭、房间推进与沃里克二阶段等表现。

它不做什么

不永久写入“已解锁”任务进度；移除 Mod 后，临时开放效果也随之消失。

版本门槛：Steam public Build 22928553

游戏更新、加入测试分支或文件哈希不同，都不要绕过版本守卫。等待作者发布兼容新版。

最容易装错的地方

下载的 ZIP 必须先解压。最终需要看到 游戏安装目录\Mods\CrucibleUnlock.dll，而不是 ZIP 文件、双层 Mods\Mods 或一整层压缩包目录。

安装或更新期间先退出游戏。AI Agent 可以协助下载、复制和只读核对；按本项目工作约束，由用户本人通过 Steam 启动游戏并完成游戏内测试。

0退出游戏，备份已有存档

  1. 确认 Steam 库中游戏不显示“正在运行”，并等 Steam 云同步结束。
  2. 按 Win + R，粘贴下面的路径，回车。
%USERPROFILE%\AppData\LocalLow\Moon Studios\NoRestForTheWicked
  1. 如果看得到 DataStore 文件夹，右键复制，到桌面或其他游戏目录外的位置粘贴。建议把副本命名为 NRFW-save-backup-日期-时间。
  2. 检查副本确实存在；原始 DataStore 留在原处，不要剪切、覆盖或删除。
新电脑可能还没有存档

如果从未进入过游戏，找不到 DataStore 是可能的。记录“没有现有存档”，继续下一步。

1找到真正的游戏目录，核对版本

  1. 在 Steam 库右键《恶意不息》→ 管理 → 浏览本地文件。弹出的文件夹就是本文的“游戏安装目录”。不要猜是 C 盘还是 D 盘。
  2. 确认这个目录同时有 NoRestForTheWicked.exe 和 NoRestForTheWicked_Data。
  3. 游戏所在 Steam 库的 steamapps 目录里应有 appmanifest_1371980.acf。可用记事本打开，查找 "buildid"，值必须是 22928553；使用 public 分支。
路径只作示例

D:\SteamLibrary\steamapps\common\NoRestForTheWicked 是作者机器上的示例，不是你必须使用的位置。后文所有 Mods、MelonLoader、UserData 都应直接位于你自己的游戏安装目录。

可选：对游戏原文件做只读哈希核对

熟悉 PowerShell 的用户可使用 Get-FileHash -Algorithm SHA256 -LiteralPath '实际完整路径'。本版守卫期望 GameAssembly.dll 为 5B00EE90833B1BE2EA73E01CB83E710E09E86199D12AC769BE3C0E82ADD8B4BB，NoRestForTheWicked_Data\il2cpp_data\Metadata\global-metadata.dat 为 4C8DFE07E5F5178F8EEFD3D079412EC164EBA5DA798EFD2A2AE03AA37DC79502。任何一项不符就停止，不要修改游戏文件。

2安装 MelonLoader 0.7.3 x64

本 Mod ZIP 不包含加载器。先到 MelonLoader 官方 v0.7.3 发布页，选择 Windows x64 的手动安装 ZIP（MelonLoader.x64.zip）。也可以按 官方安装器说明操作，明确选择兼容的 0.7.x 和正确游戏目录。

  1. 下载后在“下载”文件夹找到加载器 ZIP，右键选择全部解压。Windows 自带此功能，不需要另装解压软件。
  2. 打开解压结果，检查内容和目标位置。把加载器文件按官方包的目录结构放进游戏安装目录根部，即与 NoRestForTheWicked.exe 同层；不要放进 Mods。
  3. 复制前检查目标位置有无同名文件。如果已有加载器或其他文件会被覆盖，先识别来源与版本，不直接覆盖。
  4. 确认游戏根目录出现 MelonLoader 文件夹。本次实测安装也有同层 version.dll；不同安装方式清单可能不同，dobby.dll 是否存在不能单独证明安装成功。
此时是“文件已放置”，还不是“运行已验证”

加载器首次由用户启动游戏时才生成 IL2CPP 互操作程序集和日志，可能需要更久。可以先继续放置 Mod 和配置；游戏启动留到第 6 步由用户本人完成。

3从 Nexus 下载并校验 Mod ZIP

  1. 打开 Nexus Mods 的 Second Crucible Unlock and Encounter Fixes 文件页。
  2. 在 Main files 找到 Crucible Unlock 0.8.6，点 Manual download。若要求登录、验证码或选择下载方式，由用户按页面完成。
  3. 到 Windows 的“下载”文件夹，找到这次取得的 ZIP。不要用旧的 0.4.0 包、GitHub 自动生成的源码 ZIP 或其他镜像。
  4. 可先右键 ZIP → 全部解压。解压目录应含 Mods\CrucibleUnlock.dll、CHANGELOG.md、INSTALL.md、SHA256SUMS.txt。

Get-FileHash -Algorithm SHA256 -LiteralPath '你的下载目录\实际文件名.zip'

4把 DLL 放在唯一正确的位置

  1. 回到第 1 步找到的游戏安装目录。如果没有 Mods 文件夹，就在根目录新建一个名称恰好为 Mods 的文件夹。
  2. 从解压目录里的 Mods 文件夹复制已核对的 CrucibleUnlock.dll，粘贴到游戏根目录的 Mods。
  3. 检查文件最终完整路径：
<你的游戏安装目录>\Mods\CrucibleUnlock.dll
状态路径示意
正确游戏目录\Mods\CrucibleUnlock.dll
错误：只放 ZIP游戏目录\Mods\CrucibleUnlock-0.8.6-boss-order.zip
错误：多一层 Mods游戏目录\Mods\Mods\CrucibleUnlock.dll
错误：多一层包目录游戏目录\CrucibleUnlock-0.8.6-boss-order\Mods\CrucibleUnlock.dll

CHANGELOG.md、INSTALL.md、SHA256SUMS.txt 是阅读和校验文件，不必复制进游戏目录。如果已有同名旧版 DLL，先保持游戏退出，备份旧版并确认更新方案；不要把两个不同名字的旧版与新版 DLL 同时放在 Mods。

5写入三个必填配置项

目标文件是 游戏安装目录\UserData\MelonPreferences.cfg。如果文件已经存在，用记事本打开，保留其他 Mod 的配置。若未生成，可在游戏根目录新建 UserData 文件夹，再新建名为 MelonPreferences.cfg 的纯文本文件。先在资源管理器打开“显示文件扩展名”，避免误建成 MelonPreferences.cfg.txt。

  1. 查找 [CrucibleUnlock]。已有时只编辑该区块；没有时在文件末尾空一行后新增。不要出现两个同名区块。
  2. 确保同一区块有下面三项，拼写和引号保持一致：
[CrucibleUnlock]
mode = "runtime-unlock"
guard_broken_warrick_music = true
repair_warrick_phase2_target = true
  1. 保存，关闭记事本，再重新打开检查：runtime-unlock 带英文双引号；两个 true 不带引号，也不是 false。
只设置 mode 不够

两个沃里克修复选项在缺省时为 false。本次验收所需的三个值都应显式写出。

完成后的目录结构

NoRestForTheWicked\            ← 你自己的游戏安装目录
├── NoRestForTheWicked.exe
├── NoRestForTheWicked_Data\
├── MelonLoader\               ← 加载器
├── version.dll                ← 本次实测方式会出现

└── UserData\

6由用户启动游戏，核对日志与画面

前面完成的是离线安装。接下来由用户本人通过 Steam 正常启动游戏。第一次加载 MelonLoader 时生成 IL2CPP 程序集可能比平常慢；进入主菜单后可以正常退出，再查看日志。

  1. 打开 游戏安装目录\MelonLoader\Latest.log，用记事本的 Ctrl + F 逐项寻找以下关键内容。
MelonLoader v0.7.x
Crucible Unlock 0.8.6-boss-order 已加载
mode = runtime-unlock
guard_broken_warrick_music = True
repair_warrick_phase2_target = True
[runtime-unlock] build guard passed
[runtime-unlock] installed two targeted read overrides

日志不一定逐行相邻，但这些关键项需要确实出现。只看到“已加载”却没有 build guard passed 或两处读取覆盖记录，不能算临时解锁已生效。若首次运行重写了配置，在用户退出游戏后重新检查第 5 步的三个值。

  1. 确认日志后，用户本人再进入游戏，到第二回声献祭盆观察是否可用，并亲自测试献祭、Boss 和后续楼层。Agent 可以只读协助分析日志，但不代替用户操控游戏。
区分三种结果

“DLL 在正确目录”＝文件放置完成；“日志关键项齐全”＝运行加载通过；“献祭与关卡体验正常”＝用户实机验证通过。不要把前一项直接当成后一项。

离线安装完成清单

  • Steam public Build 为 22928553，游戏目录由 Steam 实际定位。
  • 已有存档已复制备份；若无存档，已记录。
  • MelonLoader 官方 0.7.3 x64 文件在游戏根目录。
  • Nexus ZIP 与解压 DLL 的 SHA-256 均匹配。
  • 唯一 Mod DLL 位于 Mods\CrucibleUnlock.dll。
  • 配置文件只有一个本 Mod 区块，三个值均正确。

以后如何更新或卸载

  • 更新本 Mod：先让用户正常退出游戏；备份旧 DLL 到游戏目录外，再核对新包来源和说明，只保留一个版本的 CrucibleUnlock.dll。不要在游戏运行时替换。
  • 只卸载本 Mod：退出游戏后移除 Mods\CrucibleUnlock.dll。配置区块即使保留，也不会让已经移除的 DLL 生效。
  • 卸载 MelonLoader：按 MelonLoader 官方卸载说明单独处理。不要因为卸载本 Mod 而删除整个 Mods、UserData 或存档目录。
